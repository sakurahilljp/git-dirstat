# ホットスポット（Code Churn）分析ガイド

本ドキュメントは、`git-dirstat churn`（または `git-dirstat hotspot`）を用いた**コード変更頻度・ホットスポット分析**の背景、分析理論、コマンドの使い方、および実践的な活用法を解説する利用者向けガイドです。

---

## 1. なぜホットスポット分析が必要なのか？

### 1.1 背景：静的メトリクスの限界と「動的」な変更履歴
従来のコード品質分析では、コード行数（LOC）や循環的複雑度（Cyclomatic Complexity）といった**静的なメトリクス**がよく用いられます。しかし、これらの指標には重大な弱点があります：

> **「複雑なコードであっても、滅多に変更されないのであれば、バグを生むリスクは低い」**
> **「シンプルなコードであっても、毎週のように変更が繰り返されている場所は、仕様が不安定でバグが集中しやすい」**

ソフトウェア工学（Adam Tornhill 著 *Your Code as a Crime Scene* や各種学術研究）において、**「変更頻度（コミット回数）」と「変更規模（追加・削除行数の累積 = Code Churn）」が高いコード領域（Hotspot）は、システム内で最もバグ密度が高く、保守コストを浪費している場所**であることが実証されています。

### 1.2 `git-dirstat churn` が提供する価値
`git-dirstat` のホットスポット分析は、Git のコミット履歴を走査し、**どのディレクトリやコンポーネントに開発リソース・変更が集中しているか**を素早く可視化します。

- **リファクタリング投資の最適化**: 闇雲にコードを綺麗にするのではなく、最も修正頻度が高いモジュールに優先投資できる。
- **アーキテクチャの境界劣化の検知**: 本来安定しているはずのコアモジュールや共有ライブラリが頻繁に改修されていないかを早期発見。
- **チーム・スプリントの振り返り**: 直近スプリントや四半期でどのコンポーネントに最も手が加わったかを客観的に把握。

## 2. 集計メトリクスの定義

`git-dirstat churn` では、ディレクトリごとに以下の指標を集計します。

| メトリクス | 表示名 | 説明 | 分析上の視点 |
| :--- | :--- | :--- | :--- |
| **コミット頻度** | `Commits` | そのディレクトリ配下のファイルが変更されたコミットの回数 | **変更の頻度**。この値が高いほど、仕様変更やバグ修正が頻発している。 |
| **ユニークファイル数** | `Files` | 対象期間内に変更が加わったファイルの種類数 | 影響範囲の広さ。特定ファイルに集中しているか、ディレクトリ全体に波及しているか。 |
| **追加行数** | `Added` | 期間中の累積追加行数 (`+N`) | 新機能の追加規模やコードの増大傾向。 |
| **削除行数** | `Deleted` | 期間中の累積削除行数 (`-N`) | リファクタリング、廃止、またはコードの置換規模。 |
| **変更総量 (Churn)** | `Churn` | 累積追加行数 + 累積削除行数 | **コードの流動性・不安定度**。頻繁に書き換えられている度合い。 |
| **割合・比率** | `Percent` | 全体に占める関与率（%） | プロジェクト全体における変更の集中度。 |

> [!NOTE]
> **コミット回数のカウント基準**
> 1つのコミット内で同一ディレクトリ配下の複数ファイルが変更された場合でも、そのディレクトリに対するコミット回数（`Commits`）は **1回** としてカウントされます。これにより、コミットの肥大化による歪みを防ぎ、純粋な「修正イベントの発生頻度」を捉えます。

## 3. コマンドの使い方

### 3.1 基本構文
```bash
git-dirstat churn [OPTIONS] [<revision-range>] [-- <target-path>]
```
※ `churn` の代わりにエイリアス `hotspot` も使用できます（例: `git-dirstat hotspot`）。

### 3.2 代表的なユースケースと実行例

#### ① 直近のコミット履歴からホットスポットを探す（デフォルト）
```bash
git-dirstat churn
```
HEAD から遡り、マージコミットを除外したコミット履歴を走査して、コミット頻度（`Commits`）降順でディレクトリを表示します。

#### ② 期間を指定して分析する（スプリント・四半期レビュー）
```bash
# 直近1ヶ月間のホットスポット
git-dirstat churn --since="1 month ago"

# 2026年1月1日以降のホットスポット
git-dirstat churn --since="2026-01-01"

# 特定の期間範囲を指定
git-dirstat churn --since="2026-01-01" --until="2026-03-31"
```

#### ③ コミット件数制限とインライン・バーグラフ表示
```bash
git-dirstat churn -n 100 --depth 2 --graph
```
直近 100 コミットを対象に、階層深度 2（例: `pkg/gitutil/`）で集計し、変更量のプロポーショナル・バーグラフを出力します。

#### ④ 累積変更量（Churn）順でソートし、上位5件を抽出
```bash
git-dirstat churn --sort churn --top 5
```
コミット回数ではなく、書き換え行数（Added + Deleted）の総量が多い順に上位 5 ディレクトリを絞り込みます。

#### ⑤ ブランチ間の差分履歴を分析
```bash
git-dirstat churn main..feature-branch
```
フィーチャーブランチで行われた全コミットの履歴を走査し、どのコンポーネントが集中改修されたかを分析します。

#### ⑥ 超高速走査モード (`--fast`)
```bash
git-dirstat churn --fast --since="1 year ago"
```
行単位のパッチ計算（Myers Diff）をスキップし、Git ツリー差分のみで「コミット頻度」と「ファイル数」を集計します。数千〜数万コミットの巨大リポジトリや長期分析でも数秒で完了します。

#### ⑦ CI/CD・Pull Request コメント用 Markdown 出力
```bash
git-dirstat churn -n 50 -f markdown --stat
```
GitHub / GitLab PR や Issue、`$GITHUB_STEP_SUMMARY` にそのまま貼り付け可能な GFM テーブル形式を出力します。

## 4. ホットスポット分析の実践的アクション

分析結果からホットスポットが特定された場合、以下のような改善アクションが推奨されます：

1. **高頻度変更・大規模 Churn のコンポーネント（最優先リファクタリング対象）**:
   - 単一責任の原則（SRP）に違反し、神クラスや多目的モジュールになっている可能性があります。責務を分割して独立モジュール化を検討してください。
2. **高頻度変更だが追加・削除行数が小さいコンポーネント**:
   - 設定ファイルや定数定義、あるいは if-else 分岐の追加が繰り返されている可能性があります。設定の外部化や Strategy パターンの適用が効果的です。
3. **テスト自動化の重点配置**:
   - ホットスポット領域に対してテストカバレッジが不足している場合、回帰バグが発生するリスクが極めて高くなります。該当ディレクトリのユニットテスト・結合テストを優先的に拡充してください。

## 5. 主要オプション一覧

| オプション | 短縮 | 初期値 | 説明 |
| :--- | :---: | :---: | :--- |
| `--target` | `-t` | `.` | 分析対象のベースディレクトリ（相対パス） |
| `--depth` | `-d` | `1` | 集計するディレクトリの階層深度 |
| `--sort` | `-s` | `commits` | ソートキー (`commits`, `churn`, `files`, `added`, `deleted`, `path`, `percent`) |
| `--reverse` | `-r` | `false` | 昇順/降順の反転 |
| `--top` | - | `0` | 上位 N 件のみ表示（`0` は全件） |
| `--format` | `-f` | `table` | 出力形式 (`table`, `json`, `csv`, `tsv`, `markdown`) |
| `--since` | - | - | 指定日時以降のコミットを対象 (`2026-01-01`, `30 days ago` 等) |
| `--until` | - | - | 指定日時以前のコミットを対象 |
| `--max-count` | `-n` | `0` | 走査する最大コミット数（`0` は無制限） |
| `--no-merges` | - | `true` | マージコミット（親が2つ以上）をスキップ |
| `--first-parent` | - | `false` | マージコミット時に第1親のみを辿る |
| `--fast` | - | `false` | パッチ計算を省略し、コミット回数とファイル数のみ高速集計 |
| `--percent` | - | `false` | 全体に占める比率列を表示 |
| `--graph` | - | `false` | インライン変更バーグラフを表示 |
| `--stat` | - | `false` | `--percent` と `--graph` を同時に有効化 |
| `--exclude` | `-e` | - | 集計から除外する glob パターン |
| `--no-color` | - | `false` | ANSI カラーコードを無効化 |
