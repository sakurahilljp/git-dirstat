## 2. カテゴリ別の詳細提案

### 2.1 レポーティング・可視化の拡張 (UX / Visualization)

#### ① 変更比率（%）およびインライン・バーグラフ表示（実装済み）
* **概要**: 各ディレクトリの変更行数が全体の何割を占めるかを示すパーセンテージ（`Percent`）や、`git log --stat` 風のプロポーショナル・バー（`Graph`）を出力。
* **フラグ**: `--percent`, `--graph`, `--stat`, `--sort percent`
* **ステータス**: `feature/percent-and-graph` にて実装完了。

#### ② Markdown 出力フォーマット (`--format markdown`)
* **概要**: GitHub / GitLab の Pull Request や Issue コメント、`$GITHUB_STEP_SUMMARY` にそのまま貼り付け可能な GFM（GitHub Flavored Markdown）テーブル形式を出力。
* **メリット**: CI/CD パイプライン内で実行し、PR の規模感や変更範囲のサマリーを自動コメントする Bot を容易に構築可能。
* **ステータス**: `feature/markdown-formatter` にて実装完了。
* **出力イメージ**:
  ```markdown
  | Directory | Files | Added | Deleted | Net | Percent |
  | :--- | ---: | ---: | ---: | ---: | ---: |
  | `src/components/` | 15 | 820 | 150 | +670 | 56.1% |
  | `src/services/` | 8 | 450 | 120 | +330 | 32.9% |
  | **TOTAL** | **23** | **1270** | **270** | **+1000** | **100.0%** |
  ```

#### ③ インタラクティブ TUI / ツリービュー表示 (`--tree` / TUI モード)
* **概要**: フラットな指定深度（`--depth`）集計だけでなく、階層構造をツリー状に展開・折りたたみできる TUI ブラウザ（`bubbletea` 等の利用）またはインデント付きツリー出力。
* **メリット**: 巨大リポジトリにおいて、コマンドを都度深度を変えて再実行することなく、問題のあるディレクトリを直感的にドリルダウン探索可能。

### 2.2 フィルタリングとしきい値制御 (Filtering & Noise Reduction)

#### ④ しきい値フィルタ (`--threshold` / `--min-percent` / `--min-lines`)
* **概要**: Git 本家の `git diff --dirstat=3`（全体の 3% 以上の変更があったディレクトリのみ表示）のように、一定割合または一定行数未満の微小な変更を非表示にする（あるいは `other (< 3%)` としてまとめる）機能。
* **メリット**: 設定ファイルの1行修正など、多数の細微な変更が混在する巨大な変更差分からノイズを取り除き、重要な変更にフォーカス可能。
* **フラグ例**: `--threshold 3`（3%以上のみ）、`--min-lines 50`（50行以上変更のみ）。

#### ⑤ 空白・改行コード変更の無視 (`-w` / `--ignore-all-space`)
* **概要**: 行末空白、インデント修正（スペース/タブ変換）、フォーマッタ（`gofmt`, `prettier` 等）の一括適用による改行・空白の変更を差分計算から除外。
* **メリット**: 純粋なロジック・コードの変更量のみを正確に把握。

#### ⑥ Untracked（未追跡）ファイルの取り込みオプション (`-u` / `--include-untracked`)
* **概要**: 現在のワーキングツリー比較（0引数実行）は Staged + Unstaged のみを対象とし、Untracked ファイルは除外されているが、新規作成中の未追跡ファイルも含めて集計するオプション。
* **メリット**: `git add` 前の新規フィーチャー実装作業中に、全体の開発ボリュームを把握可能。

---

### 2.3 分析軸の多角化 (Analytics & Insights)

#### ⑦ ファイル拡張子 / 言語別集計 (`--by-ext` / `--by-lang`)
* **概要**: ディレクトリ単位だけでなく、拡張子別（例: `.go`, `.ts`, `.sql`, `.md`）やプログラミング言語別に変更行数をクロス集計、あるいは拡張子別の集計モードを提供。
* **メリット**: 「実装コード」と「テストコード」「設定ファイル」「ドキュメント」の内訳を瞬時に分離。

#### ⑧ 変更頻度・ホットスポット分析 (`churn` / `hotspot` サブコマンド)
* **概要**: 2点間の単一差分だけでなく、特定コミット履歴・期間（例: 直近3ヶ月、直近100コミット）を走査し、「どのディレクトリが何回コミットされたか / 累積で何行修正されたか（Code Churn）」を集計。
* **メリット**: 頻繁に修正が加えられている高リスクなディレクトリや、リファクタリングが推奨されるホットスポットの特定を支援。
* **ステータス**: `feature/churn-hotspot` にて実装完了。詳細は [`docs/hotspot-analysis-guide.md`](hotspot-analysis-guide.md) を参照。

### 2.4 CI/CD・品質ゲート連携 (CI/CD & DevOps Integration)

#### ⑨ 変更量バジェット・品質ゲート判定 (`--max-lines`, `--fail-on-change`)
* **概要**: 特定ディレクトリの変更量が指定値を超えた場合や、コアモジュールに変更があった場合に、非ゼロ終了コード（Exit Code 3 など）を返して CI を落とす機能。
* **メリット**:
  - 「1つの PR は 500 行以内にする」という開発チームのレビューガイドラインを機械的に強制。
  - レガシー領域や保護領域の意図しない改変を自動検知。

---

### 2.5 パフォーマンス・スケーラビリティ (Performance & Concurrency)

#### ⑩ 並行パッチ計算 (Worker Pool Concurrent Diffing)
* **概要**: 現在のストリーミング処理において、ファイルごとの Myers diff 計算を Goroutine ワーカープールで並行化。
* **メリット**: 数千〜数万ファイルが変更された超巨大コミット・リベース時の Diff 処理時間をマルチコアを活用して短縮（メモリ上限をセマフォ等で抑制しつつ並列化）。
